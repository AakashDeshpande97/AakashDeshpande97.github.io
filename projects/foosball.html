Computer vision pipeline for foosball analytics and winner prediction

TypeMaster's thesis
WhenOct 2025 – Mar 2026
ContextComputer Vision Group, University of Siegen
View code on GitHubRead the thesis (PDF)Deployment case study

Overview

A complete computer vision pipeline that analyses a foosball game from a single fixed overhead webcam, with no extra sensors and no manual input. It takes a 60-second video and predicts whether White or Black wins, or whether it's a draw. Supervised by Prof. Dr. Michael Möller and Alexander Aurus.

22 playerslocalised on 8 rods in every frame, running entirely on CPU
3,184 hitsdetected and classified into 8 hit types across 41 videos
57.5%video-level accuracy (hard vote) across 3 classes, against a 33.3% random baseline

How it works

  1. CalibrateZhang's method removes lens distortion using a checkerboard.
  2. Correct perspectiveArUco markers give the table pose and a metric bird's-eye view.
  3. Track the ballColour segmentation in HSV with a Kalman filter.
  4. Find the playersIntensity profiles along each rod, smoothed with bilateral filtering.
  5. Detect hitsAn entry/exit zone state machine classifies contacts into 8 hit types.
  6. PredictA TCN with dilated causal convolutions on 25 features, with hard and soft voting.

What I did

  • Built the whole pipeline: camera calibration, perspective correction, ball tracking, player detection, hit detection and winner prediction.
  • Player positions come from intensity profiles sampled along each rod line and smoothed with bilateral filtering, which locates all 22 figurines on 8 rods per frame on a CPU.
  • The hit detector is a state machine on entry and exit zones around each player; it classifies every ball contact into one of 8 hit types.
  • A Temporal Convolutional Network reads sequences of 25 positional and temporal features. Predictions for each sequence are combined per video with hard and soft voting.
  • Refactored the pipeline into a FastAPI service in Docker, deployed to Google Cloud Run through Artifact Registry with a GitHub Actions CI/CD pipeline, and to a GKE Autopilot cluster as a second target.
